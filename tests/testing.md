# Verification process

## Offline verification

From the repository root, install the local Lua 5.1 runtime once:

```powershell
.\tools\setup-lua.ps1
```

The runtime stays in ignored `tools/lua/`; no global installation is needed.

After changing Lua, tests or verification tooling, run the full check before handoff or committing:

```powershell
.\tools\verify.ps1
```

This checks Lua/XML syntax, runs all offline Lua suites and checks the Windows addon-link and RestedXP conversion tools. Verification uses the installed runtime without downloads. Fix failures and rerun.

For a focused run while working:

```powershell
.\tools\lua\lua5.1.exe tests/options.lua
```

Replace the suite path as needed. A focused run does not replace full verification.

Keep offline tests focused on core behavior and distinct regressions; avoid duplicate scenarios and assertions about labels, colors or exact widget layout. New suites belong in `tests/*.lua`, shared fixtures in `tests/support/`. Suites are discovered automatically; keep tests out of `LockInTools.toc`.

## In-game verification

Run the checks relevant to the change. Offline mocks cannot establish native rendering, client event ordering, server delivery or third-party compatibility.

For position performance changes, keep the map open with many moving peers and hover overlapping pins while other players move, join, expire or change class/status. Check that movement and hover remain smooth, tooltip ownership does not flicker, and XP changes still update ranks immediately. Switch maps, close/reopen the map and toggle its filter during movement; retained pins must project correctly and snap to current positions on reopening. Check ranking tooltips with sharing/retention disabled and leave quiet peers long enough to expire. Record client frame cost separately from offline operation counts.

Use `/reload` for existing Lua edits; restart WoW after manifest additions. Record addon version and client build from `/lit status`, plus realm and faction. Use an isolated profile or preserved SavedVariables for fresh-install and schema checks.

Confirm old addon-generated chat/data channels are left and removed from chat-window subscriptions, including restored membership or a late join notice; unrelated channels must remain joined. Check the controls are disabled for newer-schema profiles and inspect their fit and tooltips at different UI scales.
- **Native interface:** Check Content/Settings navigation, tooltips, focus, Escape/Alt+Z, window placement and dragging at different UI scales. Confirm the same player appears once and Burned counts/averages stay correct when routes overlap; disabling positions sends no coordinates on either route. Disable or lose one route while another is available: live peers and pending replies must survive. Join/leave a guild, join/leave a party, convert between party and raid, and reload while already grouped. Include membership becoming available after login. Confirm added routes discover players, `/lit status` lists active routes, and leaving the final route expires connectivity. No custom chat or data channel may be joined, and custom-channel addon messages must be ignored. Check actual delivery across zones, instances and internal realms separately; offline mocks cannot establish server reach or throttling. Newer-schema profiles must remain read-only without traffic or saved-data changes.

Confirm settings survive reload, relog and character changes, and newer-schema profiles disable editing without changing saved data. Check the Settings tabs and their help; group-key setup, global-channel controls and shared-chat actions must be absent from Settings, Content, minimap controls and command help.

Uncheck a player and confirm they disappear from the overlay while their tab row remains visible. Right-click a peer anywhere in its row, including the Level cell. Change leader/assistant roles and party membership while the menu is open: its label and visibility must update, and a stale click must not send a different party action. On two clients, confirm suggestions reach your leader and join requests reach the selected player's group through native confirmations. Other-realm and surname-qualified names must retain their distinct identities. Actions must address the intended active player. Left-clicking a row or right-clicking your own row must not open a menu. Confirm menus open at the cursor across UI scales and automatic main-window scaling, remain within screen edges, and stay in place as the cursor moves or player data refreshes. Left-click or right-click outside the menu to close it without inviting or requesting to join. Successful and failed actions must add no LockInTools chat message.
