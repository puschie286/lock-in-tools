# Verification process

## Offline verification

From the repository root, install the local Lua 5.1 runtime once:

```powershell
.\tools\setup-lua.ps1
```

The runtime stays in ignored `tools/lua/`; no global installation is needed.

After changing Lua, tests or verification tooling, run the full check before handoff or committing:

```powershell
.\tools\verify.ps1
```

This checks Lua/XML syntax, runs all offline Lua suites and checks the Windows addon-link tool. Verification uses the installed runtime without downloads. Fix failures and rerun.

For a focused run while working:

```powershell
.\tools\lua\lua5.1.exe tests/options.lua
```

Replace the suite path as needed. A focused run does not replace full verification.

Keep offline tests focused on core behavior and distinct regressions; avoid duplicate scenarios and assertions about labels, colors or exact widget layout. New suites belong in `tests/*.lua`, shared fixtures in `tests/support/`. Suites are discovered automatically; keep tests out of `LockInTools.toc`.

## In-game verification

Run the checks relevant to the change. Offline mocks cannot establish native rendering, client event ordering, server delivery or third-party compatibility.

For position performance changes, keep the map open with many moving peers and hover overlapping pins while other players move, join, expire or change class/status. Check that movement and hover remain smooth, tooltip ownership does not flicker, and XP changes still update ranks immediately. Switch maps, close/reopen the map and toggle its filter during movement; retained pins must project correctly and snap to current positions on reopening. Check ranking tooltips with sharing/retention disabled and leave quiet peers long enough to expire. Record client frame cost separately from offline operation counts.

Use `/reload` for existing Lua edits; restart WoW after manifest additions. Record addon version and client build from `/lit status`, plus realm and faction. Use an isolated profile or preserved SavedVariables for fresh-install and schema checks.

- **Setup and persistence:** Check first-login setup, key copy/paste and saved settings across reload, relog and character changes. Use a disposable newer-schema profile to confirm saved data stays untouched.
- **Native interface:** Check Content/Settings navigation, tooltips, focus, Escape/Alt+Z, window placement and dragging at different UI scales. Exercise minimap controls and any installed DataBroker display. Check the 64×64 addon texture in the AddOns list, window title, minimap and DataBroker display for clarity, correct orientation and clean edges at different UI scales.
- **Chat and data:** On two clients sharing a realm and faction, exchange chat and group data across zones/instances. Confirm data works with chat off, reconnects after loading or connection loss, and old channels stop carrying traffic after a group switch. Exercise native password and ownership behavior.
- **Data routes:** With a configured LIT group, check guild-only, party-only, raid and overlapping guild/group/global routes for discovery, XP, Burned and positions. Native guild/group routes accept other LIT keys without authentication or group filtering. Confirm the same player appears once and Burned counts/averages stay correct when all routes overlap; disabling positions sends no coordinates on any route. Lose or reject the global channel while guild/party is available, then recover it: live peers and pending replies must survive. Join/leave a guild, join/leave a party, convert between party and raid, and reload while the global join is pending. Confirm added routes discover players, `/lit status` lists active routes, and leaving the final route expires connectivity. Check actual delivery across internal realms separately; offline mocks cannot establish server reach or throttling with the extra broadcasts.
- **Sharing options:** In Settings > Sharing, confirm chat, position and data-channel controls appear together and fit at different UI scales. Check chat autojoin, Join/Leave and position sharing/retention, and confirm all three status areas stay readable as connections change. Party / raid, Guild and Global channel must default on for fresh and existing profiles. Toggle each route and check that both sends and receives stop immediately while the remaining routes retain live peers and pending replies. Disabling Global must leave only the data channel and stop its retries, including a join that completes late. Re-enable it while its old membership is still leaving, then check recovery. Turn all three off and confirm no data exchange or reconnects, then re-enable a native route and check discovery. Confirm settings survive reload, relog and character changes, and newer-schema profiles disable editing without changing saved data. Check the four Settings tabs and their help.
- **Overview and party actions:** Check discovery and XP updates with chat and positions off, invitations and join requests through native confirmations, scrolling and stale peers. Check the narrower Name column with long names and the extra room for Region; offline regions show just the region name without `Last:`. Percentages sit beside their level values on the same horizontal line with consistent right alignment and no `~` prefix; offline values remain dimmed. Confirm local, live and saved player names remain readable without a `(you)` suffix, the local player's Actions button is disabled, and party actions address the intended active player. In both Overview and Ranking, open an Actions dropdown and left-click or right-click outside it: the menu and its tooltip must close without inviting or requesting to join.
- **Map positions:** With a fresh profile, confirm sharing defaults on and starts after login and group setup, with the first pin showing its class icon. Disable sharing, reload and change characters to confirm the saved opt-out persists with no coordinates sent; re-enable and check the first pin's class icon again. Check movement, zone/map projection, overlapping-player tooltips, stale pins and the map filter. Pins use the ranking overlay's compact tooltip: rank/name, level and XP needed unless at maximum level, then location with contact age only offline. Overlapping pins list each player's compact entry. Compare ranks and XP with the overlay, including saved/offline players and players beyond the top five; check XP updates while hovered and position-only players awaiting XP. Confirm sharing preferences hide cached locations. Status refreshes must preserve pin location and age; unavailable reports retain the last location's age. With a player in Orgrimmar, switch between Orgrimmar, Durotar and Kalimdor and repeat with a retained position. Check disabling sharing and reconnecting after loading screens.
- **Native group map markers:** Join/leave a party with the map open and convert between party and raid. Live peers represented by native markers must have one native marker and no duplicate LIT pin; leaving the native group must restore their cached LIT positions immediately. Check same-name players from different realms and raid subgroup changes. Toggle native party and raid marker filters, change map/zone and enter/leave instances: retain LIT's last-known-position fallback whenever the native marker cannot represent the player. Disconnect a grouped peer, receive an unavailable-position report and reconnect without movement; fallback and duplicate suppression must recover even while the map stays open. Close/reopen the map and toggle the LIT filter. Confirm XP, Burned, shared positions and players outside your native group keep updating, and sharing settings remain unchanged. Record native marker coverage and client frame cost separately from offline cache/refresh checks.
- **Group pin compatibility:** With OpenMap enabled, show a live party member outside the underlying Blizzard map on the stitched view. Their native/OpenMap marker must not have a duplicate LIT pin, even when the underlying map's unit-coordinate lookup is unavailable. Repeat in a raid and after `/reload` while already grouped. Check characters whose native display name or internal realm differs from their addon sender identity. Disconnect or receive an unavailable-position report, then leave the group: the retained LIT position must remain usable without changing sharing preferences.
- **Ranking:** Check live XP ordering, ties, saved/offline standings, overflow and own-row placement. Confirm names have no `(you)` suffix and each XP bar sits directly below its player's name without a blank line. Percentages and MAX sit immediately left of the level on the same horizontal line, with room for long names and no `~` prefix; offline values remain dimmed. Shift-drag the header or a row, including your own row, and confirm placement survives reload and character changes. Double-left-click the title to open Overview from a closed main window or Settings while keeping the overlay visible; single clicks, right double clicks and Shift-dragging must not open it. Hover players: line 1 is `#Rank - Name`; line 2 is `Lv Level - Missing% (Missing XP)` and disappears at max level; the final line shows location, with contact age appended only for offline players. Missing progress shows **Awaiting XP**. Check location privacy with either side's sharing off. Confirm your own row still shows its tooltip but cannot open an action menu; exercise Invite/Request to join for other players, including stale peers. Keep an action menu open through rank changes, contact expiry and group switching: it must never target a replacement player. Check Escape, outside clicks, closing/dragging and clicks through unused space.
- **Ranking position animation:** Trigger adjacent swaps, a climb through several players, a shared rank and a level-up: whole rows should glide vertically over 700 ms while rank, level and XP text update immediately. New reports must continue from each player's current visible position; unchanged refreshes must preserve timing. The rising row's backing should keep names readable during crossings. Enter and leave the top five: your row transfers between the leaders and its separate position, the lower meter/window height settles smoothly, and outgoing players briefly fade inside the ranking viewport without covering meters or accepting input. Reverse the order mid-fade and confirm each player appears once. A fading entrant becomes interactive when settled; moving established rows retain their own tooltip/menu target. Right-click and hover during swaps, then Shift-drag a row/header: motion settles before dragging and saved placement remains correct. Close/reopen, Alt+Z and switch groups while updates arrive: discard old motion and show the current order on return. Keep the existing 300 ms XP easing and gain highlight, including during row movement. Check different UI scales, short screens, screen edges, background transparency, both burning effects and long frames; native clipping, hit areas, clamping, readability and frame cost require in-game validation after `/reload`.
- **Ranking XP animation:** Gain XP locally and receive a live peer's XP report: the bar should ease forward over 300 ms with a brief pale-blue gained-segment highlight, while percentage, level, rank and hovered XP details update immediately. Check very small gains, gains from zero, rapid successive gains and near-full bars; the halo may make a subpixel gain visible but must not change the true fill width. Repeated standings/settings refreshes must neither restart nor cancel the motion. Gain enough XP to reorder players, including moving your character between the top five and its separate row: animation follows the character, and replacement rows retain their own progress. Check level-ups (including temporarily unavailable XP), maximum level, stale/offline reports, reconnecting and switching groups: establish the current value immediately without a backward tween or catch-up highlight. Close/reopen or use Alt+Z while XP changes; hidden frames must do no animation work, and reopening must show current values without replaying old gains. Check with both burned meters burning, background transparency at 100%, different UI scales and long frames; inspect native appearance, readability and frame cost separately from offline checks. Existing-file edits require `/reload`.
- **Burned meters:** Above the rankings, check the group average and reporting count; below them, drag your personal meter from 0% (fresh) to 100% (fully burned) and release to save your choice. Confirm visible tick marks at every 10% and that dragging snaps to 0%, 10%, ..., 100%, with halfway values rounding up. Existing saved values between ticks must remain unchanged until you edit them; group averages can still fall between ticks. With two clients, set 20% and 80% and confirm both show 50% with two reporting, including when chat and position sharing are off. Check rapid dragging, both endpoints, different UI scales and hiding/reopening the overlay. Hover both meters and confirm neither shows a tooltip, including with a newer-schema profile. Confirm your personal status survives reload, relog and character changes, and remains editable without a group. Check disconnects, expired reports, older clients without burned reports and group switching: unknown status must not count as 0% or retain the previous group's average. Newer-schema profiles must disable editing and leave saved data untouched. Restart WoW after adding the burned module to the manifest.
- **Burned status cooldown:** Dragging previews your choice; releasing the left mouse button commits the final value once. Check clicking the track, crossing several ticks, releasing outside the slider, and receiving group updates while dragging: only the final committed value should be shared. A successful change disables the personal control for five minutes and shows a countdown, then re-enables it without needing a group update. Selecting the current value must not start or extend the cooldown. Hide the overlay or use Alt+Z before releasing: discard the preview without saving or starting a cooldown. Confirm the remaining lock survives reload, relog, character changes, disconnection and group switching. Group averages and unchanged status heartbeats must continue updating during the cooldown; newer-schema profiles must remain untouched.
- **Burning effect:** In Settings > Ranking, confirm the Ranking info button and bottom description are absent. Confirm **Enable burning effect** defaults on and switches both meters immediately without opening a dismissed overlay or changing burned values. At 60%, check the plain meter; at 70%, 90% and 100%, check the bright hot bands, orange glow and flickering flame tips. Group averages can activate their effect independently of your personal value. Labels, slider thumb, tick marks, player rows and tooltips must remain readable and clickable, including at different UI scales and screen edges. Hide the overlay or use Alt+Z while reports arrive, then show it again: animation must stop while hidden and resume only for eligible values. An unknown/disconnected group meter must lose its effect. Toggle off and reload/relog or change characters to confirm the preference persists; newer-schema profiles must show a disabled setting and leave saved data untouched. Inspect the bundled TGA textures in the Forever client and watch frame responsiveness with both meters burning; offline tests cannot establish native appearance or frame cost. Texture primitives can be regenerated with `.\tools\generate-burning-textures.ps1`.
- **Ranking transparency:** In Settings > Ranking, drag **Background transparency** through 0%, 50% and 100%. The window backing, border and top accent must fade immediately while names, XP bars, highlights, burned meters, slider thumb, ticks and close button stay readable. Offline rows must retain their usual dimming, and the main window must keep its own background. Return from 100% to 0% and confirm the backing reappears. Close the overlay, edit transparency and confirm it stays hidden; reopen it and check the saved value. Check persistence across reload, relog and character changes, and confirm newer-schema profiles show the saved appearance with editing disabled and saved data untouched. Hover the overlay's X button and confirm no tooltip appears, including with a newer-schema profile; clicking it must still hide the overlay. Inspect native appearance at different UI scales and over bright and dark scenery; offline mocks cannot establish client rendering.
- **Tooltip placement:** Check Settings help (including checkboxes, labels, disabled controls and RestedXP input), Overview level cells, Invite/Request help, map pins, the minimap launcher, ranking player rows and your own row with default tooltip placement and any installed global tooltip positioning customization. Keep players hovered during live updates and map pin rebuilds; placement must continue following global behavior. Repeat near different screen edges and at different UI scales. Confirm leaving, tab changes, closing and dragging dismiss owned tooltips, minimap dragging suppresses its tooltip, and external DataBroker displays retain control of their own tooltip placement.
- **RestedXP import:** Open the helper without a group and import using the original owner's BattleTag. Check missing/disabled RestedXP, invalid input and large exports. Failures retain the draft; leaving the tab or closing clears guide input. Editing the source BattleTag must persist across reopening and reload, including partial input and clearing it. Confirm no group traffic or saved guide strings. Run `/lit rxp cleanup` against legacy settings and reload; only LIT's old RestedXP cache and remembered source should disappear.
- **RestedXP progress:** Compare LIT's guide count with the native importer. Import stays disabled during native processing and reports completion only after confirmed success. Close/reopen during import, then try an incorrect source, cancellation, a replacement native import and a second success when an old success message already exists.
- **RestedXP paste:** Paste small, newline-heavy and real single-line exports up to 2 MiB, including literal `|` characters. Only the byte count should appear; importing must receive the entire export. Replacing a paste, clicking Paste without pasting, moving focus and pressing Escape must retain the right draft. More than 2 MiB produces an explicit error and disables Import. Clear removes guide input and errors while retaining the BattleTag; tab/window changes clear all temporary guide input. Check busy/read-only controls and responsiveness at different UI scales.
- **RestedXP performance:** Compare paste-to-byte-count time for the same real export before/after changes, especially near 2 MiB and after repeated pastes. Record export size and pause duration separately from import time; watch for stuttering while editing the BattleTag or closing. Offline byte-integrity and bounded-widget-work checks cannot establish native clipboard performance or resolution of the reported client crash.

- **RestedXP theme:** In both classic and V2, confirm LockInTools is always available in RestedXP's theme chooser with both LIT appearance switches off. Choose it there and reload; the selection must persist without enabling the skin switch. In Settings > RestedXP, enable **Use LockInTools skin**, then disable it: restore each native profile's previous theme while preserving later manual choices. Check missing/late-loaded RestedXP, live theme preview off, reload/relog, character/profile changes, combat deferral and newer-schema LIT settings. `/lit rxp cleanup` must preserve appearance preferences.
- **RestedXP appearance:** The skin switch combines automatic theme selection, flat headers, thin borders, blue accents, modern guide checkboxes and the modern scrollbar. It and **Hide header and footer** default off. Toggle the skin and inspect the styling and restoration; manually select another theme to confirm overrides stop. Toggle hiding separately with LockInTools selected: the guide steps should fill the freed header/footer space, and `/rxp` must still open RestedXP controls. Check both interfaces, empty/collapsed guides, guide/step changes, resizing, scale, dragging, item/target panels and native redraws. Turning hiding off or selecting another theme must restore layout and controls. Toggle during combat and confirm the final choice applies afterward. Confirm the two checkboxes, transparency slider and short tooltips fit the page and preserve import drafts. Offline tests cannot establish native rendering, combat safety or compatibility with other skin addons.
- **RestedXP guide checkboxes:** With the skin enabled, inspect the flat boxes and blue checkmarks in the todo list in classic and V2. Check incomplete steps, manually skipped steps, automatic completion, disabled steps, optional steps and hidden text-only controls. Hover and click: native skip actions and compact tooltips must still work, including V2's skip-icon preview and adjacent quest links. Change guides and complete steps to exercise reused controls and native redraws. Set transparency to 100% and confirm checkbox graphics remain readable. Disable the skin or select another theme: native artwork and states must return immediately. Repeat during combat; existing controls must still reflect completion while skin activation/restoration and newly created styling wait until combat ends. Inspect different UI scales and confirm the checkbox hit area, todo text, resize grip and right-click menus behave as before.

- **RestedXP hidden controls:** With header/footer hiding on, confirm the active todo list remains visible above the guide in classic and V2. Complete steps, switch guides, resize and reload; also switch the classic active-step anchor between top and bottom. Drag the native bottom-right resize grip with the footer hidden and confirm the new size saves on release/reload. Restore the decorations or select another theme and check that anchors, borders and mouse behavior return correctly. Repeat theme/visibility changes during combat and confirm they apply afterward without losing the todo list or resize grip.

- **RestedXP transparency and scrollbar:** Select the LockInTools theme in classic and V2. Drag transparency through 0%, 50% and 100%: panel backgrounds, borders, shadows, header artwork and scrollbar track should fade while text, icons, selection highlights, checkboxes, resize grips and the scrollbar thumb stay readable. Return from 100% to 0% and confirm fills reappear immediately, including after reloading with a fully transparent saved preference. Drag repeatedly through the range while watching frame responsiveness and guide progress; changing transparency must not rebuild the guide. Check header/footer hiding on and off, guide changes and reload. Enable the skin and exercise the mouse wheel, dragging the blue thumb, clicking the track, short/no-scroll guides and resizing with the footer hidden. Confirm the scrollbar updates as guide content changes and returns to its native appearance when the skin is disabled or another theme is selected; header hiding keeps the bar available for guide selection even without a scroll range. Transparency and header/footer preferences must persist across skin toggles, reload and importer cleanup; missing RestedXP and busy imports must still allow editing, while newer-schema settings disable changes. Repeat appearance changes during combat and check the final choice afterward. Inspect native rendering, entry right-click menus, input responsiveness and slider-drag frame cost in-game; offline mocks cannot establish those.

- **RestedXP tooltips:** With the skin enabled, hover classic/V2 guide rows, skip checkboxes, quest links, item/target controls and RestedXP map pins. Check the dark background and thin border, with native text, item colors, compact skip hints and placement preserved. Move directly to bag, unit and unrelated addon tooltips: their normal appearance must return. Repeat after hiding/reopening a tooltip, switching themes, disabling the skin, native backdrop redraws and combat. The guide transparency slider must leave tooltip text and backing readable. Check global tooltip positioning addons and different UI scales; offline mocks cannot establish native rendering or frame order.
- **RestedXP right-click menus:** In classic and V2, open a guide-row context menu and the guide/settings menus. Check flat dark panels, thin borders and blue hover highlights, including nested guide groups and menus created after login. Native actions, check/radio states, custom icons, disabled entries, expand arrows, cursor anchoring, Escape and outside-click dismissal must still work. Check native V2 menu theming both on and off. Close the menu and open an unrelated addon or Blizzard dropdown: its native styling must return. Repeat after skin/theme changes, reopening menus and combat; new artwork can wait until combat ends. Check tooltip placement, different UI scales and submenu boundaries in-game.

- **RestedXP scrollbar guide selection:** With the LockInTools theme and hidden header, confirm the native scrollbar stays visible in classic and V2, including short/no-scroll, empty and collapsed guides. Collapsing must keep cached guide rows hidden while leaving the bar available. Right-click the thumb and track: the guide chooser must open once at the cursor, with flat dark panels, thin borders, blue hover highlights, native guide groups/submenus and working selection, without settings entries. Check left-click track scrolling, thumb dragging, wheel scrolling and resizing with the footer hidden; native scrolling must remain unchanged, including when there is no scroll range. Hide the top-level guide window and confirm updates never reopen it. Repeat after native redraws, late V2 window creation, reload and combat. Select LockInTools manually with the skin switch off and header hiding on: the persistent bar, shortcut and chooser styling must still work. Restore the header, choose another theme or use read-only settings: native scrollbar and ancestor visibility must return, and right-click must retain native behavior.

For the RestedXP scrollbar arrow regression, use the wheel, drag the thumb and click the track in classic and V2. Check the top, middle and bottom of a long guide: both legacy arrow buttons must stay hidden with the skin active. Repeat after resizing and changing guides, then disable the skin or select another theme and confirm native arrows return. Check frame responsiveness while scrolling.
