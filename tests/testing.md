# Verification process

## Offline verification

From the repository root, install the local Lua 5.1 runtime once:

```powershell
.\tools\setup-lua.ps1
```

The runtime stays in ignored `tools/lua/`; no global installation is needed.

After changing Lua, tests or verification tooling, run the full check before handoff or committing:

```powershell
.\tools\verify.ps1
```

This checks Lua/XML syntax, runs all offline Lua suites and checks the Windows addon-link and RestedXP conversion tools. Verification uses the installed runtime without downloads. Fix failures and rerun.

For a focused run while working:

```powershell
.\tools\lua\lua5.1.exe tests/options.lua
```

Replace the suite path as needed. A focused run does not replace full verification.

Keep offline tests focused on core behavior and distinct regressions; avoid duplicate scenarios and assertions about labels, colors or exact widget layout. New suites belong in `tests/*.lua`, shared fixtures in `tests/support/`. Suites are discovered automatically; keep tests out of `LockInTools.toc`.

## In-game verification

Run the checks relevant to the change. Offline mocks cannot establish native rendering, client event ordering, server delivery or third-party compatibility.

Use `/reload` for existing Lua edits and restart WoW after manifest changes. Record addon version and client build from `/lit status`, plus realm and faction. Use an isolated profile or preserved SavedVariables for fresh-install and schema checks.

- **Setup and persistence:** Check that first login opens the Rankings tab directly, without creating a group key or joining a custom chat channel. Dismiss it and reload/relog with the welcome message enabled: Content must stay closed. Check saved settings across reload, relog and character changes. Upgrade a preserved older profile and confirm the obsolete group, chat, global-channel and Party / raid preferences and saved shared coordinates are removed. Confirm cached ranking history and the death marker preference survive. Roll back a disposable copy of the upgraded profile to the previous release and confirm position sharing is off. Confirm old addon-generated chat/data channels are left and removed from chat-window subscriptions, including restored membership or a late join notice; unrelated channels must remain joined. Use a disposable newer-schema profile to confirm saved data and channel membership stay untouched.
- **Player data:** In Settings > General, confirm automatic cleanup defaults on and removes players last seen at least 10 days ago. Turn it off, reload and check that older history remains; turn it on and check immediate cleanup. Clear all player data: the first click requests confirmation, while switching to RestedXP or closing Settings cancels it. Confirm clearing removes old rows, preserves preferences and personal Burned status/cooldown, and allows active players to reappear through fresh updates. Check the controls are disabled for newer-schema profiles and inspect their fit and tooltips at different UI scales.
- **Native interface:** Check Content/Settings navigation, tooltips, focus, Escape/Alt+Z, window placement and dragging at different UI scales. Exercise minimap controls and any installed DataBroker display. Check the 64×64 addon texture in the AddOns list, window title, minimap and DataBroker display for clarity, correct orientation and clean edges at different UI scales.
- **Guild data route.** On two clients with Friends sharing disabled, confirm one legacy `LockInToolsData` discovery request per guild connection. Check that replies use the request's format. Verify XP, Burned, class and party-status changes arrive over compact `LITG` between full legacy snapshots. Check that every 30-second refresh carries the latest status in one legacy packet, including when a change is due on the same tick. Confirm each player appears once and Burned counts and averages stay correct. Repeat with one client on the previous release. It should discover peers immediately and see the latest values on each legacy refresh. Confirm the current client sends no shared coordinates and draws no player pins from older messages. Join and leave a guild, including membership becoming available after login. With Guild and Friends unavailable, join a party, convert it to a raid and reload while grouped. Party and raid membership must leave sharing disconnected. Check delivery across zones, instances and internal realms. Newer-schema profiles must remain read-only without traffic or saved-data changes.
- **Send diagnostics.** When WoW rejects a data send, check `/lit status` for the route and native result. Check that success on one Guild format or Friends does not hide a failure on another. A successful retry clears that failure, and disabling or leaving the route removes its diagnostic. Check for a generic error on API exceptions. Use a receiving client to verify delivery.
- **Friends data route.** Use two Forever clients in the same realm pool on different internal realms. Disable Guild sharing on both and test with WoW friendship, then Battle.net friendship alone. Check that `LITF` carries discovery and full status snapshots after the handshake. Verify two-way XP, Burned, class and party-status updates. Disable Friends sharing on one client, remove a friendship or switch characters and confirm the affected route stops exchanging status. Confirm offline friends, friends on another ruleset and friends without LockInTools receive no full status. Reload and check discovery resumes for eligible online friends. Enable sharing in a shared guild, then leave it. Check that Guild takes priority when peer contact is confirmed, Friends resumes when needed and each player appears once. Check `/lit status` and confirm the addon adds no visible whisper messages or custom chat channels.
- **General options.** In Settings > General, confirm Guild and Friends controls fit alongside ranking and player data preferences at different UI scales. Check General and RestedXP navigation and confirm the retired Party / raid and position-sharing controls are absent. Guild and Friends default on for fresh profiles and missing preferences. Existing opt-outs stay off. Toggle each route and check its sends and receives stop immediately while the other route retains live peers. Turn both off, then re-enable one and check discovery. Confirm choices survive reload, relog and character changes. Newer-schema profiles must disable editing and preserve saved data.
- **Guild and Rankings lists.** After `/reload`, open Content before opening WoW's Guild window. Check that Guild includes online and offline members of your current guild, including members without LockInTools. Check that Rankings also includes available WoW friends and lists a guildmate who is also a friend once, with shared XP when available. Toggle Guild sharing off and confirm native guild membership remains visible. While the tab is open, remove a member and then leave or switch guilds. Confirm former members disappear from Guild and remain in Rankings only if they are friends. Switch tabs with a player tooltip or party menu open and confirm it closes.
- **Rankings tab and party actions.** Check discovery, XP updates, scrolling and stale peers. Check that long names and level details fit and confirm the Rankings table has no Region column. Percentages sit beside their level values on the same horizontal line with consistent right alignment and no `~` prefix; offline values remain dimmed. Confirm local, live and saved player names remain readable without a `(you)` suffix and the Rankings tab has a Shown checkbox on each row. Uncheck a player and confirm they disappear from the overlay while their tab row remains visible. Right-click a peer anywhere in its row, including the Level cell. In both the Rankings tab and the overlay, confirm there is one party entry: Invite when you can invite the solo peer, Suggest Invite when you are an ordinary party member, or Request to join when you are solo and the peer has room in their group. Hide that entry when no party action is available, except show disabled Already in another group information for a live peer grouped elsewhere while your group has room. Confirm that information changes back to an action as either player's group status changes. Check that both menus contain only the party entry. Change leader/assistant roles and party membership while the menu is open: its label and visibility must update, and a stale click must not send a different party action. On two clients, confirm suggestions reach your leader and join requests reach the selected player's group through native confirmations. Repeat with local players whose saved names include the local realm suffix, including after `/reload`: party actions must reach them without a player lookup error. Other-realm and surname-qualified names must retain their distinct identities. Actions must address the intended active player. Left-clicking a row or right-clicking your own row must not open a menu. Confirm menus open at the cursor across UI scales and automatic main-window scaling, remain within screen edges, and stay in place as the cursor moves or player data refreshes. Hover enabled and disabled menu entries: no action tooltip must appear. Right-click inside the menu, including enabled and disabled entries: the same player's menu must reopen at the cursor without running an action. Left-click or right-click outside the menu to close it without inviting or requesting to join. Successful and failed actions must add no LockInTools chat message. Hover Rankings Level cells afterward to confirm XP details still work.
- **Native group death markers:** On two Forever clients, have one member die while the other opens the World Map. Check for one skull at the death site. Hover the skull and confirm the tooltip shows the player's name and closes when the pointer leaves, the map closes, or the skull disappears. Release Spirit and move the ghost, then reopen the map and confirm the skull is still at the original spot. Confirm it disappears on corpse recovery, on resurrection before release, and when either player leaves the group while the skull is visible. Repeat in a party and a raid, outdoors and in a dungeon. Record the client build and any cases where a skull is missing or misplaced. Only the observer needs LockInTools. In World Map Tracking, confirm **Show death markers** defaults on. Toggle it and confirm living players' native map markers still work. Check with OpenMap installed and confirm its shared position dots still work. Reload and check that the checkbox retains its saved value.
- **Death marker restoration:** With a skull visible, run `/reload` on the observer while the member is still grouped and dead or a ghost. Confirm the skull and name return at the original coordinates. Repeat after a clean quit and restart on the same character, including with a skull older than 10 minutes. Repeat with the member reviving, leaving the group, or disconnecting before the observer returns. Confirm the map is clear of that skull.
- **Minimap death markers:** With the World Map closed, check that a nearby death shows a skull and the player's red name on hover. Move around the death site and change minimap zoom, size, and rotation. The skull should stay at the death site and disappear outside the visible minimap. Check floors in a dungeon that has overlapping maps. Release Spirit, reload, and confirm the minimap still points to the original site. Toggle **Show death markers** and confirm it controls both maps. Revive or leave the group while hovering the skull and confirm the marker and tooltip close.
- **Friends.** Open Content > Friends while solo with all data channels disabled. Check a Battle.net friend playing Forever without LockInTools and a friend playing another WoW version. The Forever friend's full character name, level, zone and status should update as WoW reports changes. Confirm the list updates while open when the friend logs out, returns, switches characters or is removed in WoW. Check sorting, scrolling and switching between Friends and Rankings. Enable **Shown** for one friend and leave another unchecked. Verify that Rankings lists both friends and the overlay shows the selected friend with XP unavailable when WoW supplies only their level. Hover the friend in the ranking overlay and check that the tooltip shows the native zone when available. Sort or scroll the list and check that the selection follows the character. Enable Friends sharing on both clients while the selected friend shares XP. Confirm the Friends row disappears and the Rankings row shows the saved choice and reported XP. Uncheck **Shown**, then verify that the overlay excludes the character while Rankings still lists them. Disable Friends sharing and verify that the character returns to Friends with the same choice. Reload to confirm both checked and unchecked choices persist.
- **Ranking:** Check live XP ordering, ties, saved/offline standings, overflow and own-row placement. Confirm names have no `(you)` suffix and each XP bar sits directly below its player's name without a blank line. Percentages and MAX sit immediately left of the level on the same horizontal line, with room for long names and no `~` prefix; offline values remain dimmed. Shift-drag the header or a row, including your own row, and confirm placement survives reload and character changes. Double-left-click the title to open the Rankings tab from a closed main window or Settings while keeping the overlay visible; single clicks, right double clicks and Shift-dragging must not open it. Hover players and check that the tooltip begins with `#Rank - Name`. The next line shows `Lv Level - Missing% (Missing XP)` below max level. Missing progress shows **Awaiting XP**. An offline player gets a **Last seen** line with the contact age. Confirm your own row still shows its tooltip but cannot open an action menu; exercise Invite/Request to join for other players, including stale peers. Keep an action menu open through rank changes, contact expiry and party/raid membership changes: it must never target a replacement player. Check Escape, outside clicks, closing/dragging and clicks through unused space.
- **Ranking overlay combat visibility.** In Settings > General, enable **Show ranking overlay** and confirm **Hide ranking overlay in combat** defaults off. Enter combat and check that the overlay stays visible. Enable the combat checkbox and enter combat with a player tooltip or action menu open. Confirm both close and the overlay returns with current standings after combat. Toggle the combat checkbox during a fight to check that it applies immediately. Turn it on, run `/lit ranking off` during combat and confirm the overlay stays hidden afterward. Reload and check that the combat preference persists.
- **Ranking position animation:** Trigger adjacent swaps, a climb through several players, a shared rank and a level-up: whole rows should glide vertically over 700 ms while rank, level and XP text update immediately. New reports must continue from each player's current visible position; unchanged refreshes must preserve timing. The rising row's backing should keep names readable during crossings. Enter and leave the top five: your row transfers between the leaders and its separate position, the lower meter/window height settles smoothly, and outgoing players briefly fade inside the ranking viewport without covering meters or accepting input. Reverse the order mid-fade and confirm each player appears once. A fading entrant becomes interactive when settled; moving established rows retain their own tooltip/menu target. Right-click and hover during swaps, then Shift-drag a row/header: motion settles before dragging and saved placement remains correct. Close/reopen or use Alt+Z while updates arrive: discard hidden motion and show the current order on return. Join/leave a party while guild sharing stays connected: keep player identities and cached standings intact. Keep the existing 300 ms XP easing and gain highlight, including during row movement. Check different UI scales, short screens, screen edges, background transparency, both burning effects and long frames; native clipping, hit areas, clamping, readability and frame cost require in-game validation after `/reload`.
- **Ranking XP animation:** Gain XP locally and receive a live peer's XP report: the bar should ease forward over 300 ms with a brief pale-blue gained-segment highlight, while percentage, level, rank and hovered XP details update immediately. Check very small gains, gains from zero, rapid successive gains and near-full bars; the halo may make a subpixel gain visible but must not change the true fill width. Repeated standings/settings refreshes must neither restart nor cancel the motion. Gain enough XP to reorder players, including moving your character between the top five and its separate row: animation follows the character, and replacement rows retain their own progress. Check level-ups (including temporarily unavailable XP), maximum level, stale/offline reports and reconnecting after losing the final native route: establish the current value immediately without a backward tween or catch-up highlight. Close/reopen or use Alt+Z while XP changes; hidden frames must do no animation work, and reopening must show current values without replaying old gains. Check with both burned meters burning, background transparency at 100%, different UI scales and long frames; inspect native appearance, readability and frame cost separately from offline checks. Existing-file edits require `/reload`.
- **Burned meters.** In Settings > General, confirm **Enable Burned status** defaults on. With two clients sharing through Guild or Friends, set personal values to 20% and 80%. Join the same party and check for 50% with two reporting. Repeat in a raid and with a reporting guildmate or friend outside the group. Verify that leaving the party removes a member's report immediately and rejoining requires a fresh report. Check that solo status snapshots omit Burned. The personal meter stays editable while solo and snaps in 10% steps from 0% to 100%. Existing saved values between ticks persist until edited. Check both endpoints, different UI scales, and hiding and reopening the overlay. Hover each meter and confirm it has no tooltip. Check that reports expire and missing reports are excluded from the average. Turn Burned off during a drag. Both meters and their reserved space should disappear, the preview should clear, and outgoing snapshots should carry XP without Burned. Reload and check that the setting persists. Re-enable Burned and verify that the personal value and any remaining cooldown are preserved. Newer-schema profiles must disable editing and preserve saved data.
- **Burned status cooldown:** Dragging previews your choice; releasing the left mouse button commits the final value once. Confirm the remaining lock survives reload, relog, character changes, disconnection and party/raid membership changes. - **Burning effect:** In Settings > General, confirm the Ranking info button and bottom description are absent. Labels, slider thumb, tick marks, player rows and tooltips must remain readable and clickable, including at different UI scales and screen edges. Hide the overlay or use Alt+Z while reports arrive, then show it again: animation must stop while hidden and resume only for eligible values. An unknown/disconnected group meter must lose its effect. Toggle off and reload/relog or change characters to confirm the preference persists; newer-schema profiles must show a disabled setting and leave saved data untouched. Inspect the bundled TGA textures in the Forever client and watch frame responsiveness with both meters burning; offline tests cannot establish native appearance or frame cost. - **Ranking transparency:** In Settings > General, drag **Background transparency** through 0%, 50% and 100%.
